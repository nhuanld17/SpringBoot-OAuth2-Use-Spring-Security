`HttpSession` **không phải** là một biến toàn cục dùng chung. Nó là **per-client** (chính xác hơn là **per browser session**).

### Cơ chế hoạt động

1. Lần đầu một trình duyệt gửi request tới ứng dụng, request chưa có cookie `JSESSIONID`.
2. Servlet Container (Tomcat, Jetty, Undertow,...) tạo một `HttpSession` mới và sinh ra một **Session ID** ngẫu nhiên, khó đoán.
3. Session ID này được lưu vào object `HttpSession` (`session.getId()`) và đồng thời được trả về cho browser dưới dạng cookie `JSESSIONID`.
4. Browser lưu cookie này và tự động gửi lại trong mọi request tiếp theo.
5. Servlet Container đọc `JSESSIONID` từ cookie, dùng nó để tìm đúng `HttpSession` tương ứng rồi gắn vào `HttpServletRequest`.
6. Spring MVC chỉ đơn giản lấy `HttpSession` từ `HttpServletRequest` và inject vào Controller hoặc Service khi cần.

```
Browser
   │
   │  Request (chưa có JSESSIONID)
   ▼
Servlet Container (Tomcat)
   │
   ├── Tạo HttpSession
   ├── Sinh Session ID (ví dụ: ABC123)
   └── Set-Cookie: JSESSIONID=ABC123
   ▼
Browser lưu cookie

==============================

Browser
   │
   │ Cookie: JSESSIONID=ABC123
   ▼
Servlet Container
   │
   ├── Đọc Cookie
   ├── Tra Session theo Session ID
   └── Gắn HttpSession vào HttpServletRequest
   ▼
Spring MVC / Controller
```

### Servlet Container quản lý Session như thế nào?

Mỗi ứng dụng web có một **Session Manager** quản lý toàn bộ các session đang tồn tại.

Có thể hình dung nó như một `ConcurrentHashMap<String, HttpSession>`:

```
ConcurrentHashMap

"AAA"
   │
   ▼
HttpSession

"BBB"
   │
   ▼
HttpSession

"CCC"
   │
   ▼
HttpSession
```

Trong đó:

- **Key** là **Session ID** (cũng chính là giá trị của cookie `JSESSIONID`)
- **Value** là object `HttpSession`

Khi request tới:

```
Cookie:
JSESSIONID=BBB
```

Servlet Container thực hiện tương tự:

```java
HttpSession session = sessions.get("BBB");
```

Nếu tìm thấy thì request sẽ sử dụng đúng `HttpSession` này.

### Bên trong HttpSession có gì?

Một `HttpSession` thường chứa các thông tin như:

```
HttpSession

id = "BBB"

creationTime = ...

lastAccessedTime = ...

maxInactiveInterval = ...

attributes
    ├── username -> "Alice"
    ├── cart -> Cart(...)
    ├── otp -> "123456"
    └── SPRING_SECURITY_CONTEXT -> Authentication
```

Các object được lưu thông qua:

```java
session.setAttribute(key, value);
```

và lấy ra bằng:

```java
session.getAttribute(key);
```

### JSESSIONID là gì?

`JSESSIONID` **không phải là Session**.

Nó chỉ là **Session ID** được gửi cho browser dưới dạng cookie.

Có thể hình dung:

```
Browser Cookie
JSESSIONID = BBB
        │
        ▼
ConcurrentHashMap
key = BBB
        │
        ▼
HttpSession
id = BBB
```

Điều này có nghĩa:

- Giá trị của cookie `JSESSIONID`
- Key trong `ConcurrentHashMap`
- Giá trị trả về của `session.getId()`

đều là **cùng một Session ID**.

### Mỗi browser có một Session riêng

Do mỗi browser (hoặc cửa sổ Private/Incognito) lưu cookie riêng nên mỗi browser sẽ có một `HttpSession` riêng.

```
User A (Chrome)
    JSESSIONID = AAA
            │
            ▼
      HttpSession AAA
      { token của A }

User B (Firefox)
    JSESSIONID = BBB
            │
            ▼
      HttpSession BBB
      { token của B }

User C (Mobile)
    JSESSIONID = CCC
            │
            ▼
      HttpSession CCC
      { token của C }
```

Vì vậy khi code:

```java
session.getAttribute(SESSION_TOKEN);
```

Spring không cần biết user là ai. Nó chỉ lấy `HttpSession` mà Servlet Container đã tìm được dựa trên `JSESSIONID`, nên mỗi request luôn đọc đúng dữ liệu của phiên làm việc tương ứng.

### Ví dụ Spring lấy `HttpSession` như thế nào?

Giả sử có Controller:

```java
@RestController
@RequestMapping("/user")
public class UserController {

    @GetMapping("/profile")
    public String profile(HttpSession session) {

        String token = (String) session.getAttribute("SESSION_TOKEN");

        return "Token = " + token;
    }

}
```

Ở đây chúng ta **không hề tạo `HttpSession`**, cũng không gọi `request.getSession()`. Chỉ cần khai báo tham số `HttpSession`, Spring MVC sẽ tự động inject vào.

### Điều gì xảy ra khi có request?

Giả sử browser gửi:

```
GET /user/profile

Cookie:
JSESSIONID=ABC123
```

Quá trình xử lý có thể hình dung như sau:

```
Browser
   │
   │ Cookie: JSESSIONID=ABC123
   ▼
Tomcat
   │
   ├── Đọc cookie
   ├── Lấy Session ID = ABC123
   ├── sessions.get("ABC123")
   └── Tìm được HttpSession
   ▼
HttpServletRequest
   │
   └── request.getSession(true)
   ▼
Spring MVC
   │
   └── Thấy Controller cần HttpSession
   ▼
Inject HttpSession vào method
   ▼
Controller
```

Sau đó Spring gọi method tương đương:

```java
HttpSession session = request.getSession(false);

controller.profile(session);
```

Nghĩa là Spring thực chất chỉ làm nhiệm vụ lấy `HttpSession` từ `HttpServletRequest` rồi truyền vào method của Controller.

Khi code:

```java
String token = (String) session.getAttribute("SESSION_TOKEN");
```

thì `session` chính là object `HttpSession` mà Tomcat đã tìm được dựa trên `JSESSIONID` của request.

Nếu browser khác gửi request với:

```
Cookie:
JSESSIONID=XYZ999
```

thì Tomcat sẽ lấy một `HttpSession` khác:

```java
HttpSession session = sessions.get("XYZ999");
```

và Spring sẽ inject object đó vào Controller. Vì vậy cùng một đoạn code:

```java
session.getAttribute("SESSION_TOKEN");
```

luôn đọc đúng dữ liệu của người đang gửi request mà không bị lẫn với người khác.
